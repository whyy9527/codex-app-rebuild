## 依赖与实验顺序

先完善八项重建机制和固定实验协议，再执行前置机制消融；完成后才开始 Duolingo 网页观察。网页观察形成固定业务规格，Swift 重建随后提供真实任务的业务效果对照。前置机制实验不计作 Duolingo 复刻效果。

运行 Goal 逐项拥有八项完成契约：代码化模子、探索到 E2E、同一场景跨语言验证、失败反馈迭代、阶段自动串联、行为级进度与接续、遗漏发现、机制及业务效果消融。不能用本路线图的简写替代它。

首轮实验规模应可负担；固定模型、输入、预算、重复次数与场景后再运行。必要时先做一次可行性试跑，试跑不能当正式对照。扩展到其他课程、iOS 或更复杂策略必须由实际证据推动。

前置机制协议见 [PROTOCOL](../projects/rebuild-mechanisms/PROTOCOL.md)。结果见 [REPORT](../projects/rebuild-mechanisms/REPORT.md)；其结果不代替后续实际业务消融。

Duolingo 观察入口与恢复边界见 [观察计划](../projects/duolingo-web/OBSERVATION-PLAN.md)。浏览器接入失败不算产品证据。

Swift 工具链与 SwiftUI 类型检查已通过；当前完整 Xcode/XCUITest 不可用，原生 UI E2E 尚未执行。详见 [环境预检](../projects/duolingo-web/ENVIRONMENT.md)。
