# Roadmap

本页只维护 rebuild 仓库尚未完成的成果。Duolingo 试验已结束，案例状态与历史由 [案例状态](../projects/duolingo-web/STATUS.md)和 [历史索引](history/README.md)维护，不在此续写课程批次或运行 Goal 状态。

| 优先级 | 待完成成果 | 验收依据 |
| --- | --- | --- |
| 1 | 在新的复刻目标上实际使用统一 workflow、项目配置和原生 Goal | 新 Codex 会话能从目标开始，完成探索→模具→实现→比较，并从保存证据恢复；本轮 CLI 测试不替代该完整使用证据 |
| 1 | 把用户需求与细粒度测量建立稳定映射 | 报告先显示主页／交互／声音等需求缺口，再展开对应场景和诊断；断言数量不作为完成率 |
| 2 | 从 Duolingo 脚本中按实际消费者提取可复用采集／编译能力 | 第二个案例实际复用同一能力；减少案例顶层一次性脚本，不先批量重写或搬迁 |
| 2 | 完善动态画面、音频与跨端状态的共同准备方式 | 动态状态、采样和触发时间可复现，无法比较时有明确原因；不靠事后遮罩或放宽断言通过 |
| 2 | 在下一个真实 App 中使用 Dream-RSI 主循环 | 已有历史树／全池回放／策略部署引擎及协议检查；新案例实际恢复原版状态，用回放反馈改变探针并把发现接入模具；不恢复已结束 Duolingo，不先做消融 |
| 3 | 按实际宿主需求收敛旧 Harness/Pipeline | 原生 Goal 路径不启第二套续跑；只有已确认的兼容需求才迁移或删除旧机制 |

当前入口和职责见 [README](../README.md)、[Workflow](../workflows/rebuild/WORKFLOW.md)及 [架构](ARCHITECTURE.md)。原论文和既有实验继续保留于 [研究说明](RESEARCH.md)，新的研究实验不是上述工程工作的前置条件。
