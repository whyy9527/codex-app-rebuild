# 第二阶段：Dream-RSI 机制落地十轮

完成十轮工程修改和十次由当前 Codex 主会话根据真实反馈生成的可执行策略修订。已打通：候选代码生成、固定评价、冻结历史、策略代码开发、回放选择、再部署与对照。仍是小型机制验证，不是论文效果复现。

## 工程修改

| 轮次 | 实测缺口与落地修改 |
| --- | --- |
| 1 | 缺少模型输出约束：结构化 source/rationale 与 CLI 运行声明核对 |
| 2 | 策略能接触宿主状态：只传前缀和公开上下文，在受限子进程执行代码 |
| 3 | 原策略来自模板：用冻结回放反馈请求实际策略源码 |
| 4 | CLI 账号不可调用模型：持久化请求/回包绑定，允许主会话显式交接 |
| 5 | 原任务过于简单：加入可行性校验与固定五例装箱评价器 |
| 6 | 旧回放拒绝缺失后续：补齐论文空继续语义，轮数增加、调用数不增加 |
| 7 | 错误提案会丢失：保留失败回执并拒绝非法策略 |
| 8 | 模型交接无法续跑：在线状态、待处理候选与运行锁 |
| 9 | 缺少真实开发入口与对照条件：生成适配器、协议核对、未认证模型标记 |
| 10 | 能力没有串起来：可恢复的在线→开发→再部署→对照工作流 |

[验收回执](receipts.json)每轮均为修改前 fail、修改后 pass，轮内验收条件相同。不同轮验收不同，不能计算成整体提升率。工程测试中的替身明确标注，实际交互实验另存。

[审计](audit.json)发现 **9 轮的完整源码清单与提交完全匹配**；第 2 轮 `runtime/codex_worker.py` 的默认模型配置与提交版本不同。当时实际执行源码保存在 [快照](round-02-worker-snapshot.py.txt)，其 SHA-256 与回执匹配。保留这处偏差，没有改写历史回执，也没有宣称十轮全量源码均与提交一致。

## 十次实际策略开发

每次均绑定真实历史、回放反馈和前次提案结果，并生成完整 Python 代码；不是更换模板名称。完整 prompt、源码、解释、五档 rho 回放轨迹、原策略与提案分数在 [实验记录](experiment.json)。审计命令重新执行了全部十次策略比较，结果一致。

| 修订 | 主要变化 | 原策略分数 | 提案分数 | 结果 |
| --- | --- | ---: | ---: | --- |
| 1 | 单根起步、精修最佳叶、质量上限停止 | 0.675 | 0.6875 | 采用 |
| 2 | rho 驱动的质量期望停止 | 0.6875 | 0.6875 | 持平，保留原策略 |
| 3 | 质量加近期增益、失败分支恢复 | 0.6875 | 0.6875 | 持平 |
| 4 | 双根多样性消融 | 0.6875 | 0.675 | 退步 |
| 5 | 质量与成本联合停止 | 0.6875 | 0.6875 | 持平 |
| 6 | 加入第二世界、显式预算与失败重启 | 0.31875 | 0.31875 | 持平 |
| 7 | 一次生成即停止的消融 | 0.31875 | 0.30625 | 退步 |
| 8 | 正边际增益精修、停滞后重启 | 0.31875 | 0.31875 | 持平 |
| 9 | 移除 rho 停止的消融 | 0.31875 | 0.2 | 退步 |
| 10 | 恢复 rho 预算并按质量与增益排序 | 0.31875 | 0.31875 | 持平 |

第 6 次开始平均两个世界的分数，不能将前后列直接解释为性能下降。第二世界只有一个达到质量上限的节点，调用归一化后的超体积为零，惩罚后分数为 -0.05。任务饱和导致后续反馈缺少区分度。十次均有 AST 结构差异，但语法差异不等于十种有效机制；失败恢复等未触发分支没有效果证据。

## 在线与对照结果

首轮在线生成经历 FFD → BFD → 子集动态规划 → 贪心认证加精确回退，质量从 0.95 达到 1.0。第二轮从历史迁移通用算法，首个候选即达 1.0，更新策略停止。

| 运行 | 候选执行次数 | 最佳装箱分数 |
| --- | ---: | ---: |
| 首轮在线 | 4 | 1.0 |
| 更新后在线 | 1 | 1.0 |
| 最终固定策略 | 4 | 1.0 |
| 最终更新策略 | 1 | 1.0 |

共有 **10 份策略回包、9 份独立生成回包、10 次候选生成/执行尝试**。更新策略对照的首个请求与固定策略首个请求完全相同，复用了已有回包，仍重新执行评价。故候选次数与独立模型请求数不同。这是饱和任务上的停止机制对照，没有随机重复与新任务验证。

## 模型与复现边界

本机 Codex CLI 的现有 ChatGPT 认证返回模型不支持；[后续探测记录](model-probes.json)保留三个明确失败，失败不计作成功修订。改为项目请求/回包接口，由当前主会话读取反馈并产出代码。没有新增付费 API 或全局配置修改。此方式可审计数据关联，**不能独立证明宿主模型身份、固定模型/温度、token 或金额**，计量均记 null；不是无人值守模型循环。

其余差距：

- 装箱五例不是论文九项基准，对照仍使用训练实例，不构成泛化验证。
- 主会话在两臂之间共享上下文；独立模型响应还存在上述缓存复用，对照标记 `partial_model_unattested`。
- 开发器每次修订当前获选策略。所有被拒提案保留为证据，但未在新增世界后重新对全提案池择优；与论文完整候选池搜索有差距。
- 本次在线宽度为 1；并行能力主要由协议测试覆盖，未完成多模型并行科研实验。
- AST 限制与进程超时不是操作系统安全沙箱。只运行可信工作流产生并检查过的代码。
- 在线锁和模型交接恢复已实测；任意崩溃时刻的事务恢复、端到端墙钟预算仍未完成。
- 没有恢复视频剪辑，没有视听审美验证，不能将装箱结果外推到视频质量。

## 复核与续跑

从仓库根执行；输入和输出均须显式指定。已有完整实验只输出报告；新输出目录会停在模型请求处等待回包。

```bash
python3 -m workflows.paper.experiment --input projects/paper-v2/packing-input --out artifacts/my-paper-run --iterations 10 --max-calls 4
python3 -m workflows.paper.requests --directory artifacts/my-paper-run/requests
# 根据实际 prompt 生成源码，再用 inspect 输出的真实 digest 提交。
python3 -m workflows.paper.requests --directory artifacts/my-paper-run/requests --source artifacts/proposal.py --request-digest <digest> --rationale '<reason>'
# 重复 experiment 命令继续；不要伪造回包或将测试替身作为模型。
python3 -m workflows.paper.audit --receipts projects/paper-v2/receipts.json --experiment projects/paper-v2/experiment.json --replay --out artifacts/audit.json
python3 -m unittest discover -v
```

最终回归：50 项测试通过；十次回放重新执行一致；四项审计测试验证了真实记录及提示、回包和模型调用计数遭改动时会拒绝。项目 skill 通过格式验证。本次无媒体变更，无须媒体验证。

下一步应先恢复可实测、独立调用的模型服务，加入完整候选池再选择与有区分度的新任务、多随机种子对照，再考虑视频适配。当前结果不支持新的论文复刻百分比。
