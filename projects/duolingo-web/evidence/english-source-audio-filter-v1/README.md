# 原版浏览器音频：三个配置与原生阳性对照

只采集本任务拥有的 Edge 应用／窗口，没有麦克风或系统全局录音。三个有效源运行分别使用应用过滤、关闭 excludesCurrentProcessAudio、窗口过滤。真实选词及错误配对均发生在 READY 后约1.3秒和2.5秒，处于10秒录音内；两个 media.play 均 resolve，播放器未静音、音量为1。三段音频峰值仍为0，因此原版声学输出不可验证，不能声称原版静音或音效1:1。

初次窗口过滤在 READY 前发生 CGS 初始化断言，未形成有效录音。增加窗口模式的主线程 AppKit 初始化后重跑成功，但仍是零信号。日志、时序及失败均保留。浏览器音频子进程不可单独作为共享应用，不足以证明根因。

用更新后同一采集器默认应用过滤，实际触发 Swift 错误配对，录到5秒声音，峰值0.4755158424，RMS 0.00687744。它验证采集器能够录到原生应用输出；原生题目来自历史实例，不能作为源／新版同状态波形一致的证明。

capture-owned-audio.swift 保留原位置参数 pid、输出目录、秒数、可选 AX 动作文件和间隔，新增可选 --filter=window、--include-self-audio。capture-source-pairing-audio.mjs 对应 --filter-window、--include-self-audio；启动在 READY 前失败时保存日志及失败时序。三个有效录音和阳性对照的 WAV 与元数据在本目录；完整可取得指标见 verification-summary.json。

下一步定位本任务浏览器实际音频输出链路；不反复重启已有源状态，也不以资源文件身份或 play 调用代替声学验收。当前未建立浏览器根因或 RSI 因果收益。
