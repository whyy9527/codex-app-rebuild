# 四模型逐步比赛推演

首页使用 `causal-player.mjs`，一个人物选择区、一套播放控件，顺序播放败者组决赛和总决赛。`data/causal/models.json` 是当前可播放数据和完整性状态入口；`validate_causal.py` 从冻结输入重放全部状态链。未结束内容保持 partial，发布要求四家两场全部 ready。

## 当前授权与运行

用户取消人为调用次数上限，要求四家尽量完成两场。GPT-6.1 sol 使用现有 ChatGPT 额度、API ¥0；DeepSeek V4.1 Flash、豆包 Seed 2.1 Pro、MiMo V2.6 Pro 共用严格 ¥50 累计上限（用户2026-10-17明确批准在原¥40上追加¥10），包含失败和重试，不充值、不订阅。原先16次GPT试点、旧tactical/veto和evidence-v2账本分别保留，不能混算额度。

每家独立推演 VIT vs 100T，程序从有效事件累计地图和系列赛胜者。该模型自己的赢家随后对阵 LOUD；不读取其他模型或旧抽样的晋级者。总决赛胜者组队拥有两次禁图和A/B选择权，其余BO5禁选与选边按现有官方规则展开。

## 因果链与职责

1. 读取冻结证据，输出A/B身份、两次禁图、五图顺序和双方起始边，不输出预定赢家或比分。
2. 对实际进入的地图，输出十人模拟阵容、开局判断和顺序回合事件。
3. 程序逐事件验算区域、角色存活、击杀、下包、完成拆包和回合结束条件，累计比分、定性经济档位与连败次数。
4. 下一批输入该家已验算状态及SHA-256，再决定双方如何调整。前期保留12回合/半场批次；后续采用较短窗口，减少长响应状态错误。具体窗口保存在请求schema和validation.requested_batch_cap。
5. 地图先13分且领先2分结束，系列赛先赢三图；比赛结束后不得继续产生该图回合。

模型负责BP、选边、阵容、区域移动、交锋、经济档位和调整。程序不以固定命中率、实力权重、随机抽签或预锁比分替它决定胜负。批内是一次响应中的顺序推演，**没有逐回合脚本外部反馈**；批间才收到验算结果。状态一致不证明预测更准确，也不能证明模型在单次生成内部没有隐含叙事偏向。

无效回合及其后缀排除，合法前缀保留，下一请求从最后有效比分继续。原始响应、错误原因、接受数量和运行身份保留。MiMo 后续请求按[官方 Structured Outputs 文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)启用 `response_format: {"type":"json_object"}`，继续开启思考；这只约束JSON语法，完整结构和事件语义仍由本地校验。原先未启用阶段的响应原样留档，不追改。只能修复不改变值的已知JSON传输格式问题并留痕；不得补写击杀、拆包、路线或赢家来凑合法结果。重复请求按状态摘要和阶段拒绝；已在途请求未确认结束时不能重发。

## 来源与简化边界

七张真实底图、callout区域来自公开Valorant-API游戏资源目录，来源、UUID、坐标和图像摘要见 `data/causal/map-context.json`；特工目录及实际选用头像摘要见 `data/causal/agents.json`。路径是模型选择的真实区域ID序列，未验证区域之间的碰撞或视线，也不声称是真实比赛位置。播放器呈现区域级变化，录屏应称AI模拟。

未模拟完整FPS枪械、技能、伤害和信用点。经济是模型判断的 pistol/eco/force/half/full 档位，连败由程序累计；每回合存活重置为十人。首发沿用最近出场名单作为假设。加时从第25回合第一队先攻、逐回合换边和双方full属于显式模拟约定。

旧概率、预抽样复盘、独立Ascent战术题和 `stepwise-engine.mjs` 免费棋盘实验均不参与此链；旧文件留作历史，不接入当前首页播放器。
