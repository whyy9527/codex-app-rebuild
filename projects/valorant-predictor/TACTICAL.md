# 四模型战术沙盘

仅在现有预测器首页增加独立战术方案层，不改赛事预测数据。四模型使用同一张亚海悬城、同一十人假设阵容及 30 秒分析窗口。运行状态由 `data/tactical/models.json` 提供，只有通过校验并附运行身份凭据的原始模型方案能播放；等待与失败没有替代轨迹。

`data/tactical/context.json` 冻结地图、节点、通路、起点范围和假设。图谱从现有地图栅格生成，是二维规划辅助，不是 Riot navmesh 或 FPS 物理模拟。0 秒是默认控图后的分析起点；门视为打开，未模拟高低差、跳跃、技能、交火、经济或枪械。坐标沿既定边展开，模型负责选择节点、时间和意图。

从项目目录准备输入，不调用模型：

```sh
python3 scripts/run_tactical_models.py --out private/tactical-runs/<batch>
```

真实运行额外需要 `--execute --approval-file <approval.json>`。审批记录必须保留实际授权文字，明确本轮总上限不超过 ¥5、四个精确模型、每模型最多两次；API 密钥只读已有环境变量，GPT 走已登录 ChatGPT CLI。每次调用前写预算预留 ledger；无自动充值。只有输出格式或路线校验失败才允许一次模型纠正，不在程序里修路。网络与身份错误保留回执并停止该模型。

每批归档冻结输入、schema、各次请求、原始返回、拒绝原因和最终方案；API 请求归档不含认证头。生成费用回执：

```sh
python3 scripts/summarize_tactical_run.py private/tactical-runs/<batch>
```

费用根据真实 token 用量估算，不能当作服务商账单；无用量回执记为未知。失败尝试保留预算预留。`npm run build` 会检查地图原图摘要、通路边界和所有公开方案。浏览器测试夹具仅限独立请求拦截，不进入运行数据。

本轮已通过本地验收，并已获得用户对指定官网的提交、推送及上线授权；实际发布结果见 STATUS.md 所指回执。输入输出归档不包含用户的三篇稿件，也不修改稿件。


## 地图 BP 与首页工作区

首页使用同一个模型区切换全部内容，依次展示地图BP/起始边、固定阵容与走位、系列赛推演。结构化BP由四模型第二次真实调用生成，入口为data/veto/models.json；上海官方规则与地图池冻结在data/veto/context.json。新BP沿用各模型原有系列赛对阵，不改原比分与冠军。它与早期虚构剧情里的自定义BP是不同生成任务。

若BP没有Ascent，页面明确现有Ascent走位是独立固定场景；不自动改路线、地图或特工来凑连续性。特工同时85秒选择的规则说明不意味着现有固定十人阵容是该场真实选人。新官方结果由data/official-current.json单独列明；未改写原模型冻结赛事快照。
