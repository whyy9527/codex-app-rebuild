# Safari 查询探索：真实 RSI 至共同 E2E

本轮使用独立 Safari 原版及既有 Edge 候选。所有 UI 动作由当前 Codex 的 CUA 执行，Python 只提交一次性文件请求及读取实际回执，不启动第二个探索代理或续跑器。原版只读，重置加空查询只恢复界面基线，不恢复远程数据库。

## 固定协议与探索

新协议 `rsi-safari-queries.json` 固定发现器、独立评价器、共享原生驱动及私有 seed。三个未观察查询是假设，seed 不包含预期结果：姓名片段、姓名首字母、电话末四位。先实际验证 Safari 分行分页 AX 解析；初版误读 AX 索引的解析结果保存在私有准备目录，修正后才冻结输入和开始 collect。

原策略实际 collect 四轮，树含根及四节点，分数依次为 1/3、2/3、1、1/3。独立评价重新操作所有已发现查询。源站结果分别为10、37、7条，首屏记录顺序及分页一并保存。每次记录基线、结果、重置、最终恢复的 AX 和截图。

完整冻结池 replay 的原策略分数0.45：rho=0仍调用一次，rho=1在达到1后重新开根分支。读取实际轨迹后，复用已存在的 v1 策略参加同池比较；它在零投入和已达本协议质量1时停止，并选择当前可见的最高评分叶。原版保留参与，v1得0.46胜出。此质量仅为三个探针的实际独立重复性，不是全产品验收。

随后实际执行 collect --pool 部署胜出文件，另采三节点新世界并逐项独立评价，未复用旧 UI 回执。池检查确认两个世界，节点数[5,4]，协议 `3b5312b34734acf110f6d5eecfeddcdc6fe6a526455e5484bd156456a80326df`，选中策略 SHA256 `4d937cb04db3b2524b76bf61d04e39c80b352b83b3475baa60570fdcdfc19d68`。旧 Edge 池及中断世界未修改或拼入。

## 共同 E2E 及差异

检查实际发现及独立评价后冻结私有 `query-fragments-e2e-book.json`。原版、候选分别用同一动作驱动重新执行三场景，由同一五项断言检查：基线、结果、重置清空输入、重置保留结果、空查询恢复基线。驱动只采事实，不携带期待答案。项目入口增加对应 replay／compare 命令及公开场景。

原版15项通过。候选13项通过、2项失败：姓名首字母查询返回空结果，原版37条；该查询后的重置保留了候选空结果，因此也与原版结果不同。姓名片段与电话片段各5项通过。失败比较器实际退出1，未修改要求迁就实现。候选后端目前仅对姓名、学号、电话执行 contains，首字母能力仍需实现及复验。

Safari 与 Edge 实际窗口不同，严格截图比较 not_run；保留原始截图，不宣称前端一致。三个探针也没有覆盖多音字、其他首字母、大小写、高级筛选、写入、键盘及悬停。完整复刻 Goal 保持 active。
