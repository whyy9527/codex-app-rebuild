# 姓名首字母查询修复与实际复验

上一轮真实 Safari RSI 查询探索及共同 E2E 发现，原版首字母查询返回37条，候选为空；保留旧候选13通过／2失败的原始结果，未改冻结要求。

## 实现

Prisma 的 Student 新增持久化 nameInitials 字段，独立迁移只增加字段。使用 [pinyin-pro](https://github.com/zh-lx/pinyin-pro) 的首字母及姓名模式生成连续大写搜索值；实际锁定3.29.5，许可入口列入第三方通知。候选查询将该字段加入现有 OR contains 条件，继续在 MySQL 内按原始位置排序和分页。共享响应契约不暴露派生字段。

新导入同时生成首字母。已有数据使用独立回填命令更新派生字段，避免重新导入列表；回填不删除学员及详情。新环境执行迁移后再正常导入，已有环境在迁移后执行 `pnpm --filter @xiaogj/api db:backfill-name-initials`。

实现前用完整222条已观察私有列表验证：首字母匹配37条，首屏顺序与冻结原版结果相同。普通及姓名模式在本探针结果一致；选择姓名模式是实现决定，不证明原版内部使用该算法。其他首字母、大小写、复姓、多音字仍未实际验收。

## 实际验证

执行 Prisma generate、migrate deploy、222条回填成功，Node24.18及pnpm11.15.1下 build、typecheck、3项现有首页测试通过。确认旧API监听进程属于本项目后正常终止，启动新构建，实际监听本地3101端口。前端本轮无源码改动。

随后在真实候选页面，使用原有 `query_exploration_native.js` 驱动及不变的 `private/query-fragments-e2e-book.json` 重跑三条共同 E2E：姓名片段、姓名首字母、电话片段。每条实际记录基线、查询结果、重置后和空查询恢复状态的 AX／截图，由共同比较器判定。15项全部通过，包括37条首字母结果的总数、首屏记录顺序及分页，和重置清空输入但保留结果。

新私有证据为 `private/e2e-candidate-query-initials-fixed-20261012` 与 `private/e2e-candidate-query-initials-fixed-check-20261012`。原版15通过及旧候选失败证据保持原样。本轮未修改 RSI 固定协议、原版书或断言；这是消费已发现差异的实现轮。

严格前端像素比较仍未通过；三条查询业务通过不能替代全站业务、视觉、认证、权限和持久化验收。完整原生 Goal 保持 active。
