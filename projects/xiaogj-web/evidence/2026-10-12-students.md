# 学员列表与 MySQL 首次接入

本轮依据先前保存的原版 `private/reference/students.png` 和完整 `students.ax.txt` 实现学员信息管理初始页。未新增原版业务写入，未保存原版首页偏好。原版可能仍停留在上轮快捷配置草稿，浏览器恢复后必须观察并取消，不能假定已重置。

实现了前台业务侧栏、当前位置、页签、查询栏、批量操作栏、列表和分页入口。姓名、账号、号码及其他学员字段均从私有观察文件导入，不写入公开代码。未观察的按钮仅提示尚未完成；查询和分页不使用首屏子集伪造完整结果。页面行为、字体和几何尺寸尚未由候选浏览器观察验收。

后端新增共享 ts-rest/Zod 契约和独立 StudentsModule，通过 Prisma 7.9.1、MariaDB 驱动适配器读取 MySQL。独立 MySQL 8.4.11 绑定回环地址，数据和连接信息保存在忽略的私有目录。没有启动系统登录服务，也没有连接原版数据库。迁移定义学员及已观察列表的元数据；事务导入保持原始顺序，数据库中缺失的其余记录仍是缺口。

## 实际验证

- Turborepo 强制构建、类型检查及 Prisma Client 生成：7 项通过。
- 现有首页草稿状态测试：3 项通过。
- Prisma Migrate deploy 首次应用成功，第二次返回无待执行迁移。
- 默认学员接口返回 200，逐字段和逐行顺序等于私有原版快照。
- 数据库停机后默认接口返回 503，没有从 JSON 自动回退。
- 实际停止并重新启动 MySQL，再重启 API，直连 API 和 Vite 代理均返回与原始快照相等的数据。
- 未采集的第二页和非空搜索返回 503；非法页码返回 400。
- 候选业务路由 HTTP 返回 200，仅证明入口可提供服务，不证明视觉或交互合格。

生成的 SQL 最后多出空行，暂存后的 diff 检查发现此问题。修正后在新建的独立数据库重新应用最终迁移文件并导入，保留先前验证库，避免修改已应用迁移的校验和；正式连接指向新库。

重启后的第一次读取验证被随后停止临时 API 打断，返回 RemoteDisconnected；重新启动正式 API 后重新运行完整字段比较和代理检查才通过。保留这次被打断的事实，不将其算作成功请求。

本轮 CUA 两次选取 Edge 均报 `Sky Computer Use native pipe startup failed`，因此共同 UI 场景为 `not_run`。没有通过其他技术绕开 CUA 操作浏览器。上一轮首页严格像素比较失败的结果仍有效，不以本轮构建通过替代视觉验收。
