# 前置机制消融协议

登记日期：2026-10-10。状态：尚未执行。此协议只评价重建工具的机制，不评价 Duolingo 覆盖、Swift UI 或模型重建效果。

## 冻结与输入

实验前提交并推送当前实现及本协议，核验远端 main 与本地基线提交一致。记录基线提交、Python/Codex 版本、测试文件摘要、生产源码摘要及本协议摘要。每组使用 git archive 的独立临时副本；同一批冻结检查、临时夹具、验收标准与超时，不能为某组修改检查。

固定检查为基线中 `python3 -m unittest discover -v` 发现的全部检查。每组保存逐项通过/失败/报错、实际发现数量、输出摘要及执行耗时；数量与基线不一致则该组实验无效。测试替身、并发状态及缺陷注入均标明为机制测试，不计真实模型修复。

## 组别与精确定义

| 组 | 唯一被移除的机制 | 保留内容 |
| --- | --- | --- |
| full | 不修改 | 完整基线 |
| no_behavior_progress | 阶段快照不保留 reference_receipt/candidate_receipt 指针 | 阶段、预算、原始回执文件及验收器保留 |
| no_stop_feedback | Stop Hook 不请求模型根据反馈继续 | MCP、真实验收、预算与显式任务操作保留 |
| no_supplemental_discovery | 初版 candidate 通过后直接进入 review，跳过 discover | 完成条件、原版确认和冻结保护保留 |

变体通过隔离副本中的精确源码替换构造，替换位置与修改后摘要写入记录。替换命中数不符则停止，不扩大删除范围或修改测试。模型实验中的“去持久化行为进度”与这里的指针消融不同，后续必须单独定义。

指标是固定检查数量及其失败范围；不把检查分数变化解释为机制的独立效果大小。移除某机制可能被另一个完成门槛拦住，这证明约束仍生效，不证明作品质量下降。保持真实失败和零差异结果。

## 实际模型续跑的独立验证

机制消融前先做一轮有界原生宿主试跑，使用当前配置的默认模型，不擅自切模型：

- 显式临时项目，仅为其注册 MCP/Hook；不修改全局配置或其他项目，不自动绕过原生信任。
- 开始前记录准确宿主清单和所支持的信任/审查接口。发现、信任、执行分别报告。
- 最多三个尝试、总计最多180秒，真实 verifier；让模型保留一个尚未完成的已授权任务后尝试结束。
- 通过证据必须包含实际 Stop 事件、Hook 的继续决定、后续真实模型行动、真实验收通过和最终不再续跑。手工调用 Hook、工具或 verifier 不替代该证据。
- 若宿主、认证或审查机制不可用，保存实际失败并报告 unavailable；不将工具目录、信任状态或模型自述记为通过。
- 只记录可取得的模型配置/usage，token、费用未知时记 unknown。无凭证、账号信息或本机绝对路径进入提交。

这轮试跑只验证续跑机制；不算 App 重建完成率对照。真实业务消融须待 Duolingo 观察后，冻结场景、输入、模型、预算与重复计划另行登记；最终以独立业务验收评价各组，不用本协议检查取代。
