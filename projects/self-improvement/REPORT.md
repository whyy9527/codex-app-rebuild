# 十轮落地复核

本次先创建可运行基线，再由 Codex 修改项目代码，使用本项目的执行器与记录器保存每轮固定验收命令的修改前后结果。十次工程修改与十次自动策略循环分开报告。

| 轮次 | 实际增加的能力 |
| --- | --- |
| 1 | 候选父子关系及原子追加 |
| 2 | 冻结历史的有限得分、因果顺序和单链分支验证 |
| 3 | 超时回执、缺失执行器状态和子进程组清理 |
| 4 | 历史封印、源码快照与评估中源码变化检测 |
| 5 | 前缀合法动作、批次宽度和原子 unsupported 处理 |
| 6 | 调用／轮数预算、只读前缀策略接口与停止原因 |
| 7 | 论文公式 (1)、五档 rho、全历史比较及原策略保留 |
| 8 | 依赖激活、停用恢复与逆序资源清理 |
| 9 | 从父工作目录实际生成和评价独立候选 |
| 10 | 在线 → 冻结 → 比较 → 部署的闭环及 CLI 失败退出码 |

所有轮次修改前验收失败、修改后通过；其中一些失败是尚未实现能力导致导入失败，不是原有行为回归。同一轮内验收测试摘要保持一致。不同轮的验收测试不同，没有汇总成「质量提升」得分。

`summary.json` 给出十轮提交、前后源码摘要、验收摘要及回执 ID。报告生成器逐文件核对修改后源码与对应 Git 提交；回执见 `records/receipts.json`。

## 自动策略闭环

`policy-cycle.json` 保存另外十次真实执行的循环：生成和执行候选程序、冻结实际树、在全部已完成世界上回放多个策略代码候选、选择并部署到下一轮。每次均保存候选策略代码和前缀轨迹指标。

实际生成器是确定性线性函数改写器，不是 LLM；策略来自有限代码模板组合。十次循环共选择一次新策略，其余九次保持原策略。包括最终对照在内，共发生 32 次生成器调用。

在目标参数变化的单个简单任务上，固定策略用了 6 次生成调用、5 个顺序批次，选中策略用了 2 次调用、2 个批次，两者最佳得分均为 1/3。两者都未完美解决新目标。这不是独立样本统计验证，不能推出一般效率或视频审美提升。

## 最后审查

十轮之外的代码审查发现两个实际缺口：依赖者启动失败会遗留此次新启动的提供者；不存在的执行目录没有被拒绝。追加失败复现与修复回执，保留为 final 阶段，不冒充第十一轮。

导出保留执行结果，遮盖本机路径并关联原始摘要；原始记录未重写。完整性封印不是第三方签名。源码快照与 SQLite 留在本机忽略目录。

重新核对命令：

```bash
python3 -m workflows.self_improve.report \
  --receipts projects/self-improvement/records/receipts.json \
  --cycles projects/self-improvement/policy-cycle.json \
  --out artifacts/reverified-summary.json
```

完整限制见 `docs/ARCHITECTURE.md`。本次没有执行视频剪辑、付费模型调用或全局 hook 安装。

最终回归：31 项测试通过；项目 skill 格式验证通过；源码与提交核对、策略部署链、回执完整性、路径／敏感文本扫描及 diff 检查通过。最终回归回执 ID 为 `final-suite`。
